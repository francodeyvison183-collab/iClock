Philosophy

传统工具的困扰

臃肿、遮挡与后台黑洞

市面桌面工具常陷入两难：要么单一粗糙，要么动辄 100MB+（Electron 框架），常驻持续吞噬数百兆内存与 CPU，甚至附带弹窗与埋点；传统实体窗口还会死死遮挡代码与网页视线，打断心流。

  • ✘ 100MB+ 庞大安装包与高额内存开销
  • ✘ 实体窗口遮挡屏幕，严重阻碍鼠标操作
  • ✘ 后台定时循环轮询，持续耗电与唤醒
iClock 的极简哲学

原生、穿透与 0-Polling 协同

基于 Windows 原生底层 Win32 与 GDI+ 构建，无任何第三方依赖，单文件仅 253 KB，内存 < 15 MB。它不仅是支持完全点击穿透的悬浮倒计时，更融合了零轮询桌面灵感与原生 MCP 智能体长任务协同。

  • ✔ 单文件 253 KB，纯原生，内存稳定 < 15 MB
  • ✔ 完全点击穿透（WS_EX_TRANSPARENT），不挡鼠标
  • ✔ 纯事件驱动消息机制，桌面常驻 0.0% CPU 占用

Model Context Protocol

30 秒配置原生 MCP 服务

内置原生 stdio MCP Server (iclock.com --mcp)，无须 Node.js 或 Python 依赖。

编辑 %APPDATA%\Claude\claude_desktop_config.json，在 mcpServers 中填入：

{
  "mcpServers": {
    "iclock": {
      "command": "C:\\Path\\To\\iClock\\iclock.com",
      "args": ["--mcp"]
    }
  }
}

在项目根目录 .cursor/mcp.json 或编辑器 MCP 设置面板中填入：

{
  "mcpServers": {
    "iclock": {
      "command": "C:/Path/To/iClock/iclock.com",
      "args": ["--mcp"]
    }
  }
}

把以下提示词直接发给任意支持 MCP 的智能体（Cursor / Antigravity / Claude），它将自主配置并完成连接：

请帮我将本地桌面效率工具 iClock 接入当前环境的 MCP Server 列表。
iClock 的 stdio 可执行程序路径为当前解压目录下的 iclock.com，启动参数为 ["--mcp"]。
服务原生提供 5 大工具：iclock_ask_human（桌面置顶决策请示门禁）、iclock_timer（倒计时设定与查询）、iclock_notify（任务里程碑桌面提醒与铃声）、iclock_quote（桌面格言轮换与扩充）以及 iclock_status（系统运行状态）。
配置完成后请直接尝试调用 iclock_status 工具验证连接。

Q & A

常见问题与解答

解答关于极简架构、置顶穿透体验与安全性的核心疑问。

Q 为什么打游戏或写代码时不挡鼠标操作？
基于 Windows WS_EX_TRANSPARENT 原生 API，倒计时浮窗始终悬浮在桌面最顶层，但所有鼠标点击与滚轮事件均直接穿透到底层的编辑器、终端或游戏画面，丝毫不干扰任何操作。
Q 为什么体积只有 253 KB？
坚持纯粹原生。基于 Windows 内置的 .NET Framework 与 GDI+ 绘制，坚决不打包任何动辄上百兆的 Electron 或 Chromium 浏览器壳，运行内存稳定在 15 MB 以内。
Q 桌面格言常驻后台会消耗笔记本电池吗？
完全不会。iClock 采用纯事件消息驱动与 0-Polling 架构，静止常驻时 CPU 占用为 0.0%，彻底消除了后台定时器循环唤醒，笔记本全天候常驻零耗电。
Q 原生 MCP 服务支持哪些智能体？
内置原生 stdio MCP Server (iclock.com --mcp)，无须 Node.js 或 Python 环境，开箱支持 Claude Desktop、Cursor、Windsurf、Antigravity 等任意标准 MCP 客户端。
