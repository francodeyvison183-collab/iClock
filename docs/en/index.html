Philosophy

Why Choose iClock?

Rejecting the dichotomy of crude tools vs bloated 100MB+ Electron apps.

The Problem with Typical Tools

Bloat, Occlusion & Background Drain

Desktop tools often fall into two extremes: either crude and single-purpose, or bloated 100MB+ Electron packages consuming hundreds of megabytes of RAM and CPU, with telemetry or ads. Opaque windows block your code and workspace.

  • ✘ 100MB+ install size and massive RAM footprint
  • ✘ Opaque windows obstruct screen and block mouse clicks
  • ✘ Continuous polling loops drain laptop battery
iClock's Minimalist Philosophy

Native, Click-Through & 0-Polling

Engineered on Windows native Win32 and GDI+ APIs with zero external runtimes. Single portable executable with active RAM under 15 MB. Click-through overlay, 0-polling ambient quotes, and CLI agent collaboration.

  • ✔ Single 315 KB binary, pure native, RAM < 15 MB
  • ✔ True click-through (WS_EX_TRANSPARENT) never steals focus
  • ✔ Pure event-driven message loop, 0.0% CPU when idle

Q & A

Frequently Asked Questions

Direct answers regarding architecture, click-through behavior, and security.

Q Why does it never interfere with coding or full-screen gaming?
Powered by the native Windows WS_EX_TRANSPARENT API, digits float TopMost while all mouse clicks and scrolls pass through directly to underlying IDEs, terminals, and games without stealing focus.
Q Why is the executable only 315 KB?
Pure native C# and GDI+ rendering. Zero Electron, zero Chromium runtime, zero bulky dependencies. Active memory stays strictly under 15 MB.
Q Does ambient quote display drain laptop battery?
Not at all. Pure event-driven message handling (0-Polling). Idle CPU consumption is 0.0%, preserving battery life throughout the day.
Q Is iClock safe, clean, and ad-free?
100% open source under the MIT license. No ads, no bundled plugins, no background daemons — exit the app and every resource is released instantly.
