## 🌟 What's New in v1.16 / 主要更新内容

> v1.16 的主题是**「让状态条说真话 + 崩不再静默」**：修正三处会骗人的状态判定（Claude 等待通道读错字段、Codex 思考残留、WorkBuddy 预热冒充在线），接入 Pi 智能体，并给崩溃装上了可追查的日志。

### 🧠 Pi 智能体接入 (Pi Agent Support)

- **新接入 Pi**：监听 `~/.pi/agent/sessions/<cwd-slug>/*.jsonl` 递归会话目录。Pi 是 Node CLI，进程名与普通 node 进程无法区分，因此采用「按文件写入发现会话」而非「按进程发现」，并纳入常驻监听的基础智能体列表。
- **识别 Pi 的 camelCase 协议**：`toolCall`（工具调用）与 `toolResult`（工具输出——**不会被误当成人类输入**）。
- **内嵌思考可见**：从 assistant 文本里提取 `<think>...</think>` 思考块，作为实时「思考中」状态展示。
- **专属徽章**：状态条上 Pi 使用青色徽章，与其他智能体区分。

### 🔧 状态判定修正 (State Semantics Fixed)

- **Claude 等待通道读对字段**：waiting-input 文件里的真实 CLI 会话 UUID 在 `entries[].msg.session_id`，而不是不存在的顶层 `cliSessionId`（此前恒为 null，❓ 等待胶囊永远出不来）。同时新增新鲜度校验——shell 会遗留旧文件（实测有指向 23 天前会话的残留），现在要求 `savedAt` 在 10 分钟内且引用的会话确有活跃记录才采信。
- **Codex 思考残留清理**：工具一开始执行就清空 `session.Thought`，助手发出回复文本时也清空——完成后的思考不应在模型继续跑工具的十几分钟里一直挂在状态条上（此前 Codex 状态会卡在 11 分钟前的思考）。
- **WorkBuddy 预热过滤**：跳过 `kind=prewarm` 的暖池进程（不是真实用户会话），并停止通过 PID 复用兜底复活过期注册表（心跳超过 2 分钟即视为离线，避免 PID 被别的进程回收后出现的「幽灵在线」）。

### 💥 崩溃可追查 (Crash Diagnostics)

- **全局未捕获异常日志**：`AppDomain.UnhandledException` + `Application.ThreadException` 全部落盘到 `%APPDATA%\iClock\crash.log`，附带完整堆栈，下一次崩溃可精确定位而不是无声退出。
- **状态条越界保护**：`GetActiveTasks` 末尾无条件夹紧 `currentAgentIndex`，杜绝「同一轮里列表缩短导致索引越界」的 `index out of range`；渲染心跳再兜一层 try/catch，把完整堆栈写进 crash.log，而不是弹出一个未处理异常对话框。
